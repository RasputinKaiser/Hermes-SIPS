## Findings that change the implementation priorities

1. **Do not reimplement the runtime as though it only has in-memory exclusion.** The plan’s scheduler description is incomplete relative to the inspected baseline: `PathLockTable` is process-local, but the controller already holds a per-run flock transaction, rebuilds active path conflicts from durable state and checks persisted fencing on advance. The missing reservation domain is broader than that existing same-run protection. Resource “reservation” fields do not by themselves constitute path reservations. Existing two-controller tests run within one test process; this audit did not claim a simultaneous multi-process or cross-run safety proof.
2. **Do not build lexical indexing from scratch without measuring the existing index.** `weighted_terms` is already an indexed lexical seed source with true zero-match semantics inside Frontier. FTS/BM25 is an implementation choice still missing from backlog 12, but the phase allows an equivalent local lexical index. Determine whether the present index meets frozen relevance/latency gates before adding another index.
3. **The automatic retrieval trust gap remains after recall fixes.** Flat search adds trust metadata, but unset status/provenance/verify filters are permissive (`scripts/memory_fabric_search_filters.py:100-138`), and the hook calls it without those filters. The ranker renders the resulting records rather than enforcing Frontier eligibility/supersession. Correct zero-match and relevance ordering do not constitute safe Frontier cutover.
4. **Committed lifecycle counters and legacy self-loop outcomes are separate claim paths.** The local lifecycle patch removes routine success learning and now needs a neutral-teardown test reconciliation. Receipt-based runtime promotion remains a valuable baseline control but cannot establish truth for legacy self-loop outcome strings. Close those paths and negative tests before autonomous promotion.
5. **Profile defaults are necessary but not the complete host migration.** Local profile memory tests cover default stores/indexes under two HERMES_HOME values. Explicit `CODEX_MEMORY_FABRIC_STORE`/CLI overrides still win, the adapter uses process-global setdefault state, old CLI lookup fallbacks remain (`scripts/sips_memory_fabric.py:18-25`), and the token lens defaults to the global host DB. No full provider/profile migration receipt or in-process profile-switch isolation was proven.
6. **Freeze new dashboard feature work until the missing measurements exist.** Recent code improves inspection of existing receipts and events, but cannot display actual held-out promotion benefits, harmful-recall rates or paired deltas without the evaluator/experiment stores. Preserve user edits; do not conflate their UI redesign with these backend deliverables.
